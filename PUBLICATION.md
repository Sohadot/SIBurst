# Publication

How the SIBurst site is published, verified, and rolled back. This document
contains no credentials and no operator secrets.

**Status: not yet published.** Publication requires explicit approval
(DEC-024). Nothing in this repository deploys automatically.

## 1. Public origin

| Item | Value |
|---|---|
| Canonical origin | `https://siburst.com/` (apex domain) |
| `www.siburst.com` | Resolves to the same GitHub Pages site. GitHub Pages redirects between the apex and `www` when both are configured; the apex is canonical. |
| Source of truth | This GitHub repository |
| Publishable artifact | `docs/` on `main`, generated by `tools/build_site.py` (DEC-022) |
| Publication origin | GitHub Pages, "Deploy from a branch": `main` / `docs` |
| DNS, TLS edge, security | The DNS provider. It is infrastructure only; it runs no application code. |

Publication does not change the meaning of anything published. The claim
policy, the demonstration scope ("SYSTEM DEMONSTRATION — a model of the
SIBurst concept, not a measurement."), and every governed definition apply
unchanged. Deployment state is separate from conceptual validity.

## 2. Publication files

The build generates these files alongside the site. They are validated by
`tools/validate_site.py` and never edited by hand.

| File | Content |
|---|---|
| `docs/CNAME` | Exactly `siburst.com` |
| `docs/.nojekyll` | Empty. GitHub Pages serves the artifact exactly as built, with no Jekyll processing. |
| `docs/robots.txt` | Allows indexing and names the sitemap |
| `docs/sitemap.xml` | The 17 canonical public URLs: the root, the reference index, and 15 reference pages. The 404 page is excluded. |
| `docs/404.html` | A static, scriptless not-found page with root-relative links, marked `noindex` |

Each page declares a canonical URL, and the sitemap lists exactly those URLs.
Reference pages are canonical at their `.html` paths because the build
publishes them there. No clean-route scheme exists.

## 3. Build and validation

```
python -m pip install --require-hashes -r requirements-build.txt
python tools/validate_fixture.py
python tools/build_site.py
python tools/build_site.py --check
python tools/validate_site.py
python tools/preflight_accessibility.py
python -m unittest discover -s tests -p "test_*.py"
node --test tests/site-state.test.mjs
```

`.github/workflows/site-validation.yml` runs all of these on every pull
request and every push to `main`. It never deploys. The accessibility
preflight is machine evidence only; human Test 17 evidence is in
`ACCESSIBILITY_TEST_17.md`.

## 4. Security posture

- Every page carries a restrictive Content Security Policy in a `<meta>`
  element: `default-src 'none'`, scripts, styles, and connections only from the
  same origin, and no fonts, objects, frames, base URI, or form targets.
  Reference pages and the 404 page allow no scripts at all.
- There are no third-party runtime requests, analytics, cookies, or external
  fonts.
- GitHub Pages does not let a repository set custom HTTP response headers, so
  directives that only work as headers (for example `frame-ancestors`) are not
  in force. Adding them would require an edge configuration at the DNS/TLS
  provider. That is a separate, explicit decision; it is not part of this
  release.

## 5. Operator actions for publication

Perform these only after the explicit approval "APPROVED TO PUBLISH". The
records below follow GitHub's current documentation ("Managing a custom domain
for your GitHub Pages site"). Check that page again at the time of publication.

1. **Merge** the release pull request into `main`. Confirm that site
   validation CI is green on the merge commit.
2. **Verify the domain** (recommended, to prevent takeover): in the account's
   GitHub Settings → Pages → Add a domain, enter `siburst.com`. Create the TXT
   record GitHub shows (`_github-pages-challenge-<account>.siburst.com`) and
   complete verification.
3. **Enable Pages:** repository Settings → Pages → Build and deployment →
   Source "Deploy from a branch", branch `main`, folder `/docs`.
4. **Custom domain:** enter `siburst.com` and save. GitHub reads `docs/CNAME`,
   which already contains it.
5. **DNS** at the DNS provider:
   - apex `siburst.com`: `A` records `185.199.108.153`, `185.199.109.153`,
     `185.199.110.153`, `185.199.111.153`. Optionally add `AAAA` records
     `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`,
     `2606:50c0:8003::153` in addition to the `A` records.
   - `www`: `CNAME` to the account's `<account>.github.io` host.
   - Do not create wildcard records (`*.siburst.com`).
   - If the provider offers a proxy (for example Cloudflare's proxied mode),
     keep these records unproxied ("DNS only") at least until GitHub has issued
     the certificate and Enforce HTTPS is available. A proxy in front can
     interfere with GitHub's certificate issuance.
6. **HTTPS:** once the certificate is issued (it can take up to 24 hours),
   select **Enforce HTTPS**.
7. Run the smoke test in §7.

## 6. Rollback

If production is materially broken after deployment:

1. Identify the last known-good commit on `main`, the last commit whose site
   validation passed and whose smoke test passed.
2. Revert the faulty commit or commits with `git revert` in a pull request.
   Never rewrite `main`'s history; the evidence stays.
3. Rebuild deterministically: `python tools/build_site.py`, then
   `python tools/build_site.py --check`.
4. Re-run every validator in §3.
5. Merge. GitHub Pages redeploys from `main` / `docs`.
6. Re-run the smoke test.

Changing or removing DNS records is not the first-line rollback. Use it only if
the domain itself must be taken offline. Unpublishing is available in the
repository's Pages settings.

## 7. Post-deployment smoke test

Run after publication, against the live origin.

**Origin**
- `https://siburst.com/` returns HTTP 200 over HTTPS with no certificate
  warning. `http://siburst.com/` redirects to HTTPS once Enforce HTTPS is on.
- `https://www.siburst.com/` redirects to `https://siburst.com/`.
- The page source shows `<link rel="canonical" href="https://siburst.com/">`,
  the title "SIBurst — Naming the phase change in intelligence.", and the meta
  description.

**Interface**
- S0–S6 are reachable by scrolling and through the stage links and `#s0`–`#s6`.
- The enhanced demonstration loads: the persistent panel appears and the
  browser console shows no errors.
- With JavaScript disabled, all seven stages, their figures, and the reference
  layer remain readable.
- With reduced motion enabled, S4 shows two discrete states.
- Mobile portrait, desktop, and a short viewport (400% zoom) all keep 24
  entities and 4 anchors.

**Reference**
- `https://siburst.com/reference/` loads.
- At least `foundation-thesis.html`, `interface-contract.html`, and
  `decision-log.html` load, with working navigation.

**Public files**
- `https://siburst.com/robots.txt` and `https://siburst.com/sitemap.xml` load.
- A missing path such as `https://siburst.com/does-not-exist` returns 404 with
  the SIBurst not-found page.

**Security**
- There is no mixed content.
- The browser network panel shows requests only to `siburst.com`.
- The CSP `<meta>` is present in the page source.

## 8. Accessibility after publication

Activating the domain does not change the interface. The human Test 17 result
carries over only while no accessibility-relevant content changes, that is:
semantic markup, accessible text, focus order, live-region behavior, SVG
accessibility, stage navigation, or the transition record. Any such change
requires Test 17 to be repeated on the resulting commit
(`ACCESSIBILITY_TEST_17.md`).
